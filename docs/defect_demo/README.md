# Defect demo

## Faulty vs. corrected length check

This is a deliberately introduced fault for demonstration purposes, it is turned off by default.

In the faulty version, the description length is checked on the raw text before `.strip()`, so padded input is measured wrong: `"  " + 200 chars + "  "` gets rejected with `400` (because it is 204 characters raw), and `"   "` (3 spaces) gets accepted and sent to the AI as an empty string. The corrected version trims first and only then checks the length.

Both versions can be found in `validate_description()` in [app/validator.py](/app/validator.py), the faulty branch is marked with `DELIBERATE FAULT`.

### Running the faulty version

To run the tests against the faulty version, set `CALORIEHUNTER_SIMULATE_FAULT=1`:

```bash
CALORIEHUNTER_SIMULATE_FAULT=1 uv run pytest -v -p no:cacheprovider
```

This results in `5 failed, 61 passed`, the output can be found here:

[test_run_faulty.txt](test_run_faulty.txt)

### Running the corrected version

```bash
uv run pytest -v -p no:cacheprovider
```

This results in `66 passed`, the output can be found here:

[test_run_corrected.txt](test_run_corrected.txt)

### Tests that catch the fault

- `test_acceptance.py::test_ac3_length_boundary` (the padded 200 character input returns 400)
- `test_acceptance.py::test_ac4_empty_input` (`"   "` returns 200)
- `test_api.py::test_ac4_empty_and_whitespace_rejected[   ]`
- `test_validator.py::test_description_trimmed_and_bounds`
- `test_validator.py::test_description_rejected[   ]`

The unpadded 200/201 cases still pass with the fault, the cases that catch it (padded 200 in AC3 and `"   "` in AC4) were already in the tests generated by Antigravity.
